## 你应该形成的项目定位

Akashic 是面向持续陪伴场景的个人 Agent：支持对话、工具执行、长期记忆、主动消息与后台任务。面试的核心价值在于 Agent 的运行工程：事实保存、权限划分、插件组合、并发提交、取消与恢复。

对照依据：[项目介绍](../README.md)、[需求与设计原则](../docs/projectneed.md)、[当前组合入口](../bootstrap/tools.py)、[默认发行组合](../bundles/base.toml)。

建议先准备 Python 异步与类型协议、SQL 事务、HTTP 流式响应、LLM tool calling 四项基础。React 前端与 Computer/Host Bridge 作为加分路线。

## 学习时遵循的证据规则

1. 每个结论至少能指向一个当前符号或调用点；重要取舍再看 ADR。
2. 区分“需求要求”“当前代码实现”“本地实测”“正式环境验收”。四者不能互相替代。
3. [docs/NOW.md](../docs/NOW.md) 仍记录组合边界、外部插件、真实设备等后续验收；不要说全栈已完成生产验证。
4. 文档索引也会滞后：例如其中出现的 `agent/tools/unified_exec.py` 不在当前文件树，实际从 [standard_tools](../plugins/standard_tools/) 和 [host_execution](../plugins/host_execution/) 追踪。
5. 历史 `_handbook` 用于理解产品背景；例如 Proactive 指南中的“核心 runtime 负责判断与投递”，不能据此推断当前业务属于 Core，须核对插件实现。
6. 文档中的建议、练习与预期均是学习辅助，不替代原项目需求。开发时回到 [项目阅读索引](../docs/INDEX.md) 和 [工作流](../docs/WORKFLOW.md)。

## 准备完成的标准

- 不看笔记，5 分钟画出输入、回复、模型、工具、账本、送达的关系。
- 10 分钟定位“旧模型草稿为什么不能执行工具”的提交检查。
- 能解释三组区别：生成重试与工具重试、压缩与删除、进程崩溃与宿主断电。
- 至少留下三份个人证据：一次完整链路记录、一组异常恢复观察、一个可演示的小改动。
- 简历中明确自己的贡献；学习开源项目不能写成独立设计和生产落地。
